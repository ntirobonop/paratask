# v0.2 — Task Details

## 1. User stories

- As a user, I can open a task from Inbox and see its current data.
- As a user, I can edit the title and description without pressing a Save button.
- As a user, I can leave Task Details and later see the persisted changes.
- As a user, I can complete a task from Task Details and restore its completion.
- As a user, I can delete a task and undo the deletion.

## 2. Acceptance criteria

1. Tapping a task row in Inbox opens Task Details for that task.
2. Task Details displays the persisted title, description, and completion state.
3. Editing a non-blank title or description is saved automatically after a short debounce.
4. Navigating back flushes valid pending edits before closing Task Details.
5. Reopening the task displays the saved title and description.
6. Temporarily clearing the required title does not overwrite the last valid persisted title.
7. Completing a task from Task Details updates its completion state; unchecking it restores the task.
8. Deleting a task soft-deletes it, returns to Inbox, and displays `Задача удалена` with `Отменить`.
9. Tapping `Отменить` after deletion restores the task to Inbox.
10. A missing task ID shows a recoverable error state with navigation back to Inbox.

## 3. Domain changes

- Keep the existing `Task` and `TaskId` models unchanged.
- Keep title as a required non-blank domain value when persistence occurs.
- Treat title and description edits as a temporary UI draft until a valid snapshot is persisted.
- Keep completion and deletion as independent task states.

## 4. Database changes

- Keep Room schema version 1; all fields required by v0.2 already exist.
- Replace the one-way `softDelete` DAO operation with `setDeleted`, which can set or clear `deletedAt` atomically with `updatedAt`.
- Continue observing a task by ID even after completion or soft deletion so Undo and the active details flow can resolve it.
- Do not use destructive migration.

## 5. Repository changes

- Replace `deleteTask(id)` with `setDeleted(id, deleted)` in `TaskRepository`.
- Set `deletedAt = now` when deleting and clear it when restoring.
- Continue using `updateTask(task)` for autosaved title and description changes.
- Preserve injected clock and deterministic repository tests.

## 6. UI state

`TaskDetailsUiState` contains:

```kotlin
data class TaskDetailsUiState(
    val isLoading: Boolean = true,
    val taskId: TaskId,
    val title: String = "",
    val description: String = "",
    val isCompleted: Boolean = false,
    val hasPendingChanges: Boolean = false,
    val taskMissing: Boolean = false,
)
```

- The ViewModel owns the editable draft.
- Valid edits autosave after a 500 ms debounce.
- Back navigation flushes valid pending edits first.
- A blank draft title remains local and never replaces the last valid database value.
- One-off close, delete, and error signals use UI events rather than persistent state flags.

## 7. UI components

- Task Details top app bar with Back and overflow actions
- completion checkbox
- editable title field
- editable description field
- delete action in the overflow menu
- loading state
- missing-task state
- shared snackbar host for deletion Undo after returning to Inbox

Only functional v0.2 controls are shown. Dates, reminders, labels, projects, sections, subtasks, and comments remain hidden until their corresponding increments.

## 8. Navigation changes

- Inbox task rows become selectable.
- Add an application-level destination state for Inbox and `TaskDetails(TaskId)`.
- Back from Task Details returns to Inbox after pending valid edits are persisted.
- Delete returns to Inbox and hands the deleted task ID to the shared snackbar flow.
- Keep navigation deliberately small for the two current destinations; adopt a larger navigation framework when additional top-level destinations require a real back stack.

## 9. Tests

- DAO test covers delete and restore without changing schema version 1.
- Repository test covers `deletedAt` and Inbox visibility for delete/restore.
- Task Details ViewModel tests cover initial loading, debounced autosave, blank-title protection, back flush, completion toggle, deletion, and missing tasks.
- Compose tests cover populated fields, title editing, completion interaction, delete action, and missing-task state.
- App-level integration test covers Inbox → Task Details → edit → back → reopen.
- Existing v0.1 Inbox, persistence, and Quick Add tests remain green.

## 10. Migration requirements

- No Room migration is required because schema version 1 already contains title, description, completion, and deletion columns.
- The exported schema JSON must remain byte-for-byte unchanged.
- CI continues validating committed Room schemas and the full test suite.
