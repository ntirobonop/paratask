# v0.1 — Inbox vertical slice

## 1. User stories

- As a user, I can see when my Inbox is empty.
- As a user, I can quickly create a task with a title and optional description.
- As a user, I can close and reopen the application without losing tasks.
- As a user, I can complete a task and undo the action.

## 2. Acceptance criteria

1. Given an empty Inbox, launching the application displays the Inbox empty state.
2. Tapping the FAB opens Quick Add, focuses the title field, and opens the keyboard.
3. Entering `Купить продукты` and tapping Create adds the task to Inbox.
4. A created task remains in Inbox after application restart.
5. Completing a task removes it from Inbox and displays an Undo snackbar.
6. Tapping Undo restores the completed task to Inbox.

## 3. Domain changes

- Add `Task` and `TaskId`.
- Enforce non-blank task IDs and non-blank titles at task creation.
- Completion sets `isCompleted`, `completedAt`, and `updatedAt` atomically.
- Undo completion clears `completedAt` and updates `updatedAt`.

## 4. Database changes

- Add Room database version 1 and `TaskEntity`.
- Add `TaskDao` queries for active Inbox tasks, task observation, insert/update, completion, and soft deletion.
- Order Inbox tasks by `sortOrder`, then `createdAt`.
- Export and commit schema version 1.

## 5. Repository changes

- Add `TaskRepository` in `core:data` and `DefaultTaskRepository`.
- Map between `TaskEntity` and `Task` explicitly.
- Inject ID and time providers for deterministic tests.

## 6. UI state

```kotlin
data class InboxUiState(
    val tasks: List<Task> = emptyList(),
    val isLoading: Boolean = true,
)
```

Quick Add owns a `TaskDraft` with title and description active. Future properties can exist in the draft model but are not displayed as inert controls.

## 7. UI components

- Inbox top app bar
- empty state
- task list and task row
- completion checkbox
- FAB
- Quick Add bottom sheet
- completion snackbar with Undo
- bottom navigation shell

## 8. Navigation changes

- App start destination is Inbox.
- Selecting a task is reserved for v0.2 Task Details.
- FAB opens Quick Add as modal UI without creating a second navigation destination.

## 9. Tests

- DAO filters completed and deleted tasks.
- Repository persists task creation and completion timestamps.
- Inbox ViewModel emits tasks and supports completion/undo.
- Compose test covers empty state and Quick Add focus.
- Process restart persistence is covered by a Room-backed integration test.

## 10. Migration requirements

- Database version 1 has no upgrade migration.
- The exported version 1 schema becomes the baseline for all future migration tests.
- Destructive migration is prohibited for production builds.

5. End-to-end tests, documentation update, and `v0.1.0` tag.
