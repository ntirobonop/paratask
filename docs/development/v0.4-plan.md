# v0.4 — Upcoming

## 1. User stories

- As a user, I can browse tasks for any day in a visible Monday-to-Sunday week.
- As a user, I can move to the previous or next week without opening a separate calendar.
- As a user, I can return to the current day and current week with one action.
- As a user, I can see which days in the displayed week contain active tasks.
- As a user, I can create a task from Upcoming with the selected date prefilled.
- As a user, I can complete a task from Upcoming and undo that action.

## 2. Acceptance criteria

1. Upcoming displays exactly seven consecutive days from Monday through Sunday.
2. The current selection is visually distinguishable and the task list shows only active tasks for that date.
3. Days that contain one or more active tasks show a task indicator.
4. Completed and soft-deleted tasks do not contribute to indicators or the selected-day list.
5. Previous and next actions move the displayed week by exactly seven days and preserve the selected weekday.
6. The Today action selects the device's current local date and returns to its week.
7. Quick Add opened from Upcoming starts with `dueDate = selectedDate`.
8. The user may change or clear the contextual date before creating the task.
9. Changing a task's date in Task Details updates the Upcoming indicators and selected-day list after returning.
10. Completing a task removes it from the selected-day list and displays the existing Undo action.
11. Inbox, Today, and Upcoming navigation preserves the expected selected top-level destination when Task Details is opened and closed.

## 3. Domain changes

- Keep `Task.dueDate: LocalDate?` as the scheduling source of truth.
- Add a small pure week model that derives an ISO Monday week start and its seven dates.
- Keep the selected date as UI state rather than adding it to the persisted domain model.
- Inject the current local date at the Upcoming boundary so week and Today-action tests are deterministic.

## 4. Database changes

- Keep Room schema version 1.
- Add one observation query for active tasks in an inclusive ISO date range.
- Query the displayed week in one database flow rather than creating seven per-day observations.
- Order range results by `dueDate`, then `sortOrder`, then `createdAt` for deterministic grouping.

## 5. Repository changes

- Add `observeTasksInDateRange(startDate, endDate): Flow<List<Task>>`.
- Validate that the end date is not before the start date.
- Map `LocalDate` boundaries to the existing ISO-8601 Room columns.
- Keep `observeToday` as the focused Today API until the later universal `TaskQuery` increment.

## 6. UI state

`UpcomingUiState` contains:

```kotlin
data class UpcomingUiState(
    val today: LocalDate,
    val selectedDate: LocalDate,
    val weekStart: LocalDate,
    val weekTasks: List<Task> = emptyList(),
    val isLoading: Boolean = true,
)
```

- `weekDates` is derived as `weekStart + 0..6 days`.
- `taskCountByDate` is derived from active `weekTasks` for indicators and accessibility text.
- `selectedTasks` is derived by exact `selectedDate` equality.
- Changing the selected day inside the current week does not restart the Room observation.
- Changing the week switches the observed date range.

## 7. UI components

- Upcoming top app bar with a Today action
- week header with previous/next actions and month/year context
- seven selectable day cells labelled Monday through Sunday
- active-task indicator on each populated day
- existing shared task list, task row, composer, date picker, bottom navigation, and snackbar
- Upcoming empty state scoped to the selected date

The v0.4 calendar is a focused week strip, not the later full Calendar view. The separate Quick Add ergonomics work in issue #11 remains outside this increment.

## 8. Navigation changes

- Activate the Upcoming bottom-navigation destination.
- Support Inbox, Today, and Upcoming as top-level app destinations.
- Back from Task Details returns to the top-level destination from which the task was opened.
- Browse remains visible but inactive until Projects in v0.5.
- Upcoming preserves its selected date while Task Details is open during the current app process.

## 9. Tests

- Pure week-model tests cover Monday/Sunday boundaries and cross-month/year weeks.
- DAO test covers inclusive range boundaries plus completed/deleted exclusion.
- Repository test covers range mapping and invalid boundaries.
- Upcoming ViewModel tests cover selection, week navigation, Today, indicators, contextual creation, completion, and Undo.
- Upcoming Compose tests cover the seven-day strip, selection, indicators, navigation actions, and contextual Quick Add.
- App integration test covers navigation to Upcoming and return from Task Details.
- Existing v0.1–v0.3 tests remain green.

## 10. Migration requirements

- No Room migration is required because v0.4 only queries the existing `due_date` column.
- The exported schema JSON must remain unchanged.
- CI continues checking committed Room schemas after every build.
