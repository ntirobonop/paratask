# v0.5 — Projects

## 1. User stories

- As a user, I can open Browse and see my active projects in manual order.
- As a user, I can create a project with a name, color, and icon.
- As a user, I can rename a project and change its color or icon.
- As a user, I can move a project up or down in the manual order.
- As a user, I can archive a project and restore it later.
- As a user, I can delete a project without deleting its tasks.
- As a user, I can open a project and see its active tasks.
- As a user, I can create a task inside a project with that project preselected.
- As a user, I can select Inbox or an active project before creating a task.
- As a user, I can change a task's project in Task Details.

## 2. Acceptance criteria

1. Browse is an active bottom-navigation destination and lists non-deleted projects.
2. Active projects appear before archived projects and retain their manual order after restart.
3. Creating a project requires a non-blank name and persists its selected color and icon.
4. Editing a project updates its name, color, and icon without changing its tasks.
5. Move up/down actions persist a deterministic manual order.
6. Archiving removes a project from the active list, keeps its tasks assigned, and allows restore.
7. Deleting a project removes it from Browse and moves its tasks to Inbox; tasks are never deleted.
8. Opening an active project displays only its active, non-deleted tasks.
9. Quick Add inside a project starts with that project selected.
10. Quick Add from Inbox, Today, or Upcoming displays the Project property with Inbox selected by default.
11. Selecting a project before creation assigns the task to it; the task appears in that project and no longer appears in Inbox.
12. The contextual project may be changed back to Inbox before task creation.
13. Task Details displays the Project property and autosaves assignment changes.
14. Returning from Task Details restores the project screen from which the task was opened.

## 3. Domain changes

- Add Project with ProjectId, name, color, icon, archived/deleted timestamps, and manual order.
- Validate non-blank ProjectId and project names.
- Represent the icon with a closed ProjectIcon enum so persisted values remain stable.
- Keep task ownership in the existing nullable Task.projectId; null continues to mean Inbox.
- Deleting a project keeps all tasks and clears both projectId and the future sectionId.

## 4. Database changes

- Increase Room schema from version 1 to version 2.
- Add the projects table with active/archive/delete state and manual order.
- Rebuild tasks during migration to add a foreign key from project_id to projects.id.
- Use ON DELETE SET NULL as a final database safeguard.
- Preserve every v1 task; any unexpected orphan project_id is normalized to NULL.
- Add active-project ordering and project-task query indexes.

## 5. Repository changes

- Add ProjectRepository and DefaultProjectRepository.
- Observe active and archived projects separately.
- Support create, update, archive/restore, soft delete, and move up/down.
- Perform project deletion and task reassignment in one Room transaction.
- Add TaskRepository.observeProjectTasks(projectId).
- Add optional projectId to task creation.
- Validate project assignment in both create and update operations.

## 6. UI state

- BrowseUiState contains active projects, archived projects, loading state, and editor state.
- ProjectUiState contains the selected project and its active tasks.
- The task composer draft gains projectId.
- Active projects are exposed to task composer and Task Details as selectable options.
- Project editing keeps a local draft until the user confirms Create or Save.

## 7. UI components

- Browse top app bar, active Projects section, archived Projects section, and create FAB.
- Project row with icon, color, name, task count where available, move actions, and overflow actions.
- Project editor sheet with name, fixed color palette, and fixed icon palette.
- Project screen reusing the shared task list and task composer.
- Project selector row in Task Composer showing Inbox or the selected project.
- Project selector in Task Details.

The first project editor uses curated palettes rather than arbitrary color or icon input. This keeps
stored values valid and accessible while leaving room for a richer picker later.

## 8. Navigation changes

- Activate Browse in bottom navigation.
- Add Browse as a top-level destination.
- Add a project-detail destination beneath Browse.
- Back from a project returns to Browse.
- Back from Task Details returns to the originating project when opened there.
- Archived projects remain manageable from Browse but are not offered for new task assignment.

## 9. Tests

- Domain tests cover identifier and name validation.
- DAO tests cover active/archived ordering, project tasks, archive/restore, and transactional deletion.
- Migration test opens a v1 database as v2 and verifies task preservation plus the foreign key.
- Repository tests cover mapping, assignment validation, reordering, archive, and deletion behavior.
- Browse ViewModel and Compose tests cover create/edit/archive/restore/reorder/delete.
- Project ViewModel and Compose tests cover contextual creation and task completion/Undo.
- Composer tests cover Inbox/project selection and contextual defaults.
- Task Details tests cover project autosave.
- App integration tests cover Browse navigation and return from Task Details to a project.
- Existing v0.1–v0.4 tests remain green.

## 10. Migration requirements

- Register an explicit MIGRATION_1_2; destructive fallback is forbidden.
- Export and commit Room schema 2.json.
- Verify migration using Room's migration test helper and a persistence integration test.
- Keep migration code after v0.5 so direct upgrades from every released database remain supported.
